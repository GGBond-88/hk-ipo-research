## Code Review Issues

### CR-001: timeline.py CLI `__main__` missing prior-enrichment preservation check
- Status: Resolved
- Description: `src/hk_ipo/enrichments/timeline.py` lines 170-171 directly loads the record from the categorized single file and calls `_enrich_one` without checking whether enriched data already exists in `ENRICHED / f"{ticker}.json"`. This silently discards all prior enrichment blocks (geo, country, industry, etc.) when the timeline enrichment is run via CLI single-file mode after other enrichments have been applied. This is the SAME bug pattern (SR-002/CR-001) that was already fixed in `capex_opex.py` (lines 155-157), `commitment.py` (lines 133-135), and `esg_tag.py` (lines 156-158), but was MISSED in timeline.py. The `run()` function (line 128) correctly uses `load_enriched_or_categorized()` which handles this, but the CLI `__main__` block bypasses `run()` for single files. The missing code is: `enriched_file = ENRICHED / f"{ticker}.json" / if enriched_file.exists(): / record = _json.loads(enriched_file.read_text(encoding="utf-8"))`. This bug also has NO corresponding test coverage — neither a unit test in `tests/test_enrichments_timeline.py` nor a blackbox test in `tests/e2e/test_l5_timeline_blackbox.py` covers this scenario, unlike capex_opex and esg_tag which both have dedicated `test_cli_preserves_prior_enrichments` tests.
- Decision Reason: Fixed in src/hk_ipo/enrichments/timeline.py lines 173-175. The CLI __main__ block now checks if ENRICHED/{ticker}.json exists and loads the prior enriched record before calling _enrich_one, preserving all prior enrichment blocks. Regression test tracking added in revise task P0-2b.

### CR-003: test_loader_dry_run_does_not_modify_db uses wrong enriched directory
- Status: Resolved
- Description: `tests/e2e/test_pipeline_e2e.py` lines 217-225: `test_loader_dry_run_does_not_modify_db` calls `run_stage_cli("storage.loader", "--all", "--db", str(db_path), "--dry-run")` without passing `--enriched-dir`. The loader's argparse default (`src/hk_ipo/storage/loader.py` line 222: `default=str(ENRICHED_DIR)`) resolves to the project's `data/enriched/`, NOT the isolated `tmp_path/data/enriched/` where the pipeline wrote the enriched files. If the project's `data/enriched/` is empty or absent, the test vacuously passes (`process_all` prints a warning and returns early with `{"loaded": 0, "total": 0}`). If there happen to be pre-existing files in the project's `data/enriched/`, the test reads data from the wrong directory. The DB non-modification assertion is still valid regardless, but the test does not verify that `--dry-run` works on the isolated pipeline output, masking potential bugs in dry-run behavior against real enriched records.
- Decision Reason: Fixed in tests/e2e/test_pipeline_e2e.py lines 223-224. The test now passes --enriched-dir str(isolated_data_dir / "enriched") to scope the loader to the test's isolated tmp directory, ensuring the dry-run assertion runs against the actual pipeline output.
