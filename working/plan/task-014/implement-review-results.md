### CR-003: Regex keyword patterns fail to match common morphological variants (plurals, gerunds, derived nouns)
- Status: Resolved
- Description: In `src/hk_ipo/enrichments/capex_opex.py`, the compiled regexes `_FINANCIAL_KW` and `_CAPEX_KW` use strict `\b` word boundaries but the keyword stems do not account for common suffix variations. Proven cases:
  - `\brepay\b` (line 22) cannot match "repayment" or "repaying" -- text "repayment of bonds" matches ZERO financial keywords (bonds also fails `\bbond\b`), so it would be classed as opex or default-capex despite being unambiguously financial.
  - `\bfacilit\b` (line 36) cannot match "facility" or "facilities" -- text "storage facilities" matches ZERO capex keywords (confirmed via regex test).
  - `\brefinanc\b` (line 22) cannot match "refinancing" or "refinance" -- mitigated when "debt"/"loan" also present, but breaks for text like "refinancing of obligations."
  - `\bbond\b` cannot match "bonds", `\bloan\b` cannot match "loans" -- plural financial terms are missed.
  Each misclassification is a silent wrong tag in the production enrichment pipeline. Note: these patterns were inherited from the task specification (Step 3), but the implementer is responsible for production correctness. Fix: replace stems with alternations (e.g. `repay(ment|ing)?`, `facilit(y|ies)`, `refinanc(e|ing)`, `bond(s)?`, `loan(s)?`) or switch to prefix/suffix-tolerant matching.
- Decision Reason: Fixed all three regex pattern groups (_FINANCIAL_KW, _OPEX_KW, _CAPEX_KW) with comprehensive morphological alternations covering: plurals (-s/-es), gerunds (-ing), past participles (-ed), derived nouns (-ment/-tion/-sion), and y/ies alternations. Added 11 targeted tests for the specific CR-003 morphological gaps. All 24 capex_opex tests and full suite (318 tests) pass.

### CR-004: Multi-word regex keywords cannot match when final word is pluralized; `build(ing|s)?` still cannot match "buildings"
- Status: Resolved
- Description: The regex morphological fixes from CR-003 add one level of suffix variation (e.g., `build(ing|s)?`) but the trailing `\b` on the outer alternation group prevents matching words with two suffix levels. Verified via direct regex test:
  - `src/hk_ipo/enrichments/capex_opex.py:39`: `build(ing|s)?` cannot match "buildings". After matching "building" (build+ing), the trailing `\b` requires a word boundary after "g", but "s" is a word character, so the match fails. The existing test `test_capex_buildings` passes only because `classify_capex_opex` defaults to `"capex"` when no keyword matches at all (line 69) -- the keyword is never actually matched. If future code changes the default, or if "buildings" appeared in a mixed-category text where financial/opex keywords are also present, the classification could be wrong.
  - `src/hk_ipo/enrichments/capex_opex.py:31`: `operating\s*expense` cannot match "operating expenses" (plural). "Operating expenses" is a core OPEX term in HKEX prospectuses. The `\b` at end requires a non-word char after the final "e" of "expense", but the "s" in "expenses" is a word char, so the match fails and the text falls through to default "capex".
  - `src/hk_ipo/enrichments/capex_opex.py:32`: `marketing\s*campaign` cannot match "marketing campaigns". Same `\b` boundary issue on the final word.
  - `src/hk_ipo/enrichments/capex_opex.py:46`: `data\s*center` cannot match "data centers".
  Fix: For multi-word keywords where the final word can pluralize, add an optional `s?` before the trailing `\b`. Specifically: change `operating\s*expense` to `operating\s*expenses?`, `marketing\s*campaign` to `marketing\s*campaigns?`, `data\s*center` to `data\s*centers?`, and change `build(ing|s)?` to `build(ings?)?` (or `build(ing|ings|s)?`) to cover "building" and "buildings".
- Decision Reason: Fixed all multi-word keyword patterns in _OPEX_KW and _CAPEX_KW to accept pluralized final words: (1) operating\s*expense -> operating\s*expenses?, marketing\s*campaign -> marketing\s*campaigns?, sales\s*force -> sales\s*forces?, sales\s*team -> sales\s*teams? (2) build(ing|s)? -> build(ings?|s)?, data\s*center -> data\s*centers?, new\s*(store|branch|office) -> new\s*(stores?|branch(es)?|offices?), manufacturing\s*(plant|line|facility) -> manufacturing\s*(plants?|lines?|facilit(y|ies)), r\s*&\s*d\s*(center|facility|lab) -> r\s*&\s*d\s*(centers?|facilit(y|ies)|labs?).
